# 低销量长尾品广告方案

用于已上架一段时间、月销约 0–5 单、有库存、运营主动认为"也该投点广告"的批量商品。真新品/冷启动走 `campaign-plan.md`；已有稳定投放要降 ACOS 走 `optimize-existing.md`。

## 0. 先把预期写在方案第一行

月销 1–2 单的商品，广告能做到的只有三件事：

1. 用一笔**可控的固定月花费**换少量稳定增量单；
2. 用搜索词报表回答"这个品到底有没有需求"，为留/清决策提供依据；
3. 配合清库存加速动销。

不承诺把长尾品做成动销品。用户说"投广告冲销量"时，先说明结构性限制再给方案，不要用常规新品话术掩盖。

## 1. 为什么不能套用常规流程

四条硬约束决定了这条路径必须和 `campaign-plan.md` / `optimize-existing.md` 不同，方案里要向运营讲明：

1. **样本永远不够。** 按 `calculations.md` 的零订单门槛，目标 CVR 5%、容许误判 10% 时约需 45 次点击才能说"这个词不转化"；CVR 3% 时约 76 次。这类商品在 1–2 元/天预算下一个月只有十几次点击。→ 暂停和否定按**累计点击**判断，不按日历天数。3/7/14 天节奏在这里只会误停还没跑够样本的词。
2. **小样本下 ACOS 没有意义。** 一单进出就让 ACOS 在无穷大和 15% 之间跳。→ 单品决策用**绝对金额**止损线，不用 ACOS 阈值。ACOS 只在累计到门槛后才参与判断。
3. **日预算有下限。** 日预算低到买不起一次点击时，活动整天不出量，样本更慢，钱照花。→ 预算必须集中和轮投，不能全批同时开。
4. **全店筛选找不到它们。** `sales product-performance` 默认 `--min-prior-units 3`、`--min-sessions 20`，月销 1–2 单的品达不到门槛，不会出现在候选里。→ 这批 ASIN 只能由运营给出，或用 `inventory slow-moving` / `inventory aged` 反向取；不要声称是从 `store-screening.md` 筛出来的。

## 2. 只读取数（最小集）

全批目标约 6–10 次调用，按需取，不逐个 ASIN 重复。

| 目的 | 命令 |
| --- | --- |
| ASIN→唯一 SKU、可售性、Listing 问题 | `listing mine --account <店铺> --marketplace <站点> --asin "ASIN1,..."`（一次最多 20 个） |
| 本店真实销量基线（确认是 1–2 单还是真 0 单） | `sales stats --account <店铺> --asin <ASIN> --start <90天前> --end <昨天>` |
| 有没有货、压货多严重（决定投还是清） | `inventory slow-moving`、`inventory aged` |
| 是否已经在投、投了多少 | `ads coverage`、`ads performance --start --end`（跨度 >31 天会自动分段） |
| 已投品的搜索词现实 | `ads wasted-spend --min-clicks <提高后的值>`（自动分段）、`ads report-run --type search-terms` |
| 单个 ASIN 在合并活动里的表现 | `ads report-run --type advertised-products` |

取数注意：

- 广告数据只保留约 95 天，90 天是可查窗口的实际上限，不要请求更早的区间。
- `ads report-run` 单张报表最多 31 天，本地会直接拦下更长的跨度；需要 60–90 天时自己分段，或改用会自动分段的 `ads performance` / `ads wasted-spend`。
- `ads wasted-spend` 默认 `--min-clicks 10` 对长尾品偏低——10 次点击远不到零订单门槛，照搬会把"样本不足"误判成"浪费"。用它时把窗口拉到 60–90 天并显式提高 `--min-clicks`，结果仍只当候选。
- 不要为了"看起来完整"补查费用、A+、图片和历史报表；这些不改变本路径的分档结论。

## 3. 分档（本路径的核心）

不要给每个 ASIN 都写一份完整方案。先按"广告能不能起作用"分四档，只有 A/B/C 档进入结构设计。**按顺序判定，前面命中就不再往下走**，每档都要写出判据来源。

### D 档 · 不投（先修或先清）

命中任一条即列入，不生成任何广告动作：

- 无有效 SKU、不可售、被压制、无库存、无 Featured Offer/Buy Box —— 硬阻断，先修（来源：`listing mine`、`listing issues`、`pricing buybox`）。
- 价格明显高于同款竞品且无差异化 —— 广告只会买到高跳出，先调价。
- 无评论或评分明显偏低 —— 点击进来也不转化，先解决评论。
- 库龄老且核心词无市场需求信号 —— 用促销/清货处理（来源：`inventory aged` + 市场 MCP）。

D 档必须写清"这不是广告问题"，不要用广告掩盖承接问题。

### C 档 · 保命曝光（最低档）

有货、Listing 健康，但市场需求本身很小，或市场 CPC 明显高于可承受 CPC。

- 只投 1–3 个最精准的长尾 Exact，竞价不超过可承受 CPC。
- 目的是维持曝光和持续收集搜索词，**不期待 ROI**；方案里直接写"这档是维持成本"，并给月度花费上限。
- 不给这档加预算，也不因为它 ACOS 高就反复调价。

### B 档 · 试探（有需求但没验证）

市场有相关搜索量，本店无广告覆盖或覆盖极少，Listing/价格/库存都过关。

- 单活动 Exact 长尾 3–8 词，跑到累计点击门槛再判断。
- 这是"花钱买一个明确答案"的档，止损线必须**在方案里预先写死**，不到期再商量。

### A 档 · 值得加注

已有零星广告订单，或已有明确转化搜索词，且 Listing、价格、评论、库存都过关。

- 预算集中到已转化词的 Exact，其余收缩。
- 扩预算仍受 `calculations.md` 的安全幅度和经济性验证约束；没有目标 ACOS 或成本时不 prepare 扩预算。

## 4. 结构：能合并就合并，不拆三件套

- 默认 **1 个 ASIN = 1 个 Manual Campaign = 1 个广告组**。不拆 Exact/Phrase/Broad 三件套——小预算拆三份的结果是三个都拿不到样本。
- 需要少量探索时，把 Phrase 词和 Exact 词放进**同一个广告组**（同一广告组允许混用匹配方式），共用一份预算，不为匹配方式单独开活动。`campaign-plan.md` 的多活动比例结构不适用于本路径。
- **同搜索意图的近似变体合并投放**：同款不同色/不同尺寸放进同一活动的 `products` 数组（CLI 支持 1–20 个商品），共享预算和关键词，让累计点击更快到门槛。每个 ASIN 的单独表现用 `ads report-run --type advertised-products` 回读，合并不会让谁在出单变得看不清。
- **不同产品不合并**。共享关键词会让不相关商品互相拉低点击率和转化。
- 想用低竞价 Auto 活动做词发现时，说明当前 CLI 的 `keyword-campaign-launch` 只创建 MANUAL 定向，把 Auto 列为 Seller Central 人工项，不要在方案里假装能一键创建。
- 创建后状态默认 `PAUSED`，由运营确认后再启用；启用即开始花钱。

## 5. 预算：从月度总盘倒推，不从单品野心倒推

```text
目标 CPA = 售价 × 目标 ACOS        （无目标 ACOS 时用盈亏平衡 ACOS；两者都无则标"经济性未验证"并给区间）
可承受 CPC = 预期转化率 × 目标 CPA
单品月度试错上限 = 目标 CPA × 期望月增量订单数
单品日预算 = 单品月度试错上限 / 30
```

**两个数打架时不要糊弄。** 若算出的日预算低于约 2 × 可承受 CPC（买不到一两次点击），说明这个品在当前竞价水平下投不起，应降到 C 档或列入 D 档；不要靠"预算给少一点"硬开，那只会得到一个既花钱又没结论的活动。

**批次总盘与轮投：**

```text
全批同时开的月固定花费 = Σ 各 ASIN 日预算 × 30
```

超过运营能接受的总盘时，**不要按比例削减每个品的预算**——那样所有品都拿不到样本。改为**分批轮投**：按分档优先级取 5–8 个 A/B 档先跑满一个判断周期，出结论后换下一批。方案必须列出本轮投放的、本轮不投的（及原因）、以及下一轮候选顺序。

## 6. 关键词：宁少勿多

- 每个活动 3–8 个 Exact 长尾词。词越多，单词累计点击越慢，越久拿不到结论。
- 证据门槛不降低：仍按 `research.md`，每个 Exact 词必须有外部数值流量证据、指标周期和购买意图结论，并给出"关键词—来源—指标及周期—购买意图—商品匹配度—匹配方式"表。
- 优先选**竞争低、意图窄**的词。大词在这里只会烧完预算不出单；高流量不能覆盖意图不匹配。
- 不投竞品品牌词。长尾品没有预算承受品牌词的高 CPC 和低转化，还多一层商标风险。
- 竞价起点 = min(市场建议 CPC, 可承受 CPC)。市场 CPC 高于可承受 CPC 时不跟价，改投更长尾的词或降档。

## 7. 判断周期：按累计点击，不按天

本路径用 7/30/90 三个节点，替代默认的 3/7/14：

| 节点 | 触发 | 判断内容 |
| --- | --- | --- |
| 第 7 天 | 日历 | 只查是否失控：有没有花钱、CPC 是否远超预期、搜索词是否明显跑偏、有没有断货或丢 Buy Box。除止损外不调价。 |
| 第 30 天 | 日历，或累计点击达到零订单门槛的一半 | 有转化词→保留并考虑集中预算；全部零单→**先降竞价**再说，检查是不是竞价过高导致点击太贵、样本买得太少。 |
| 第 90 天 | 日历（广告数据保留期上限），或累计点击达到零订单门槛 | 门槛已到且零单→停该词/该活动，记为"已验证无需求"；有单→算真实 CPA 与 ACOS，决定升 A 档还是维持 C 档。 |

零订单门槛按 `calculations.md`：`ln(容许误判概率) / ln(1 - 目标CVR)`。长尾品用保守 CVR 假设（3%–5%），对应约 45–76 次点击。把这个数字连同下面这行写进方案：

```text
拿到结论的预计成本 ≈ 零订单门槛点击数 × 预计 CPC
```

这是长尾品方案里最该让运营先看到的数字。**如果它已经超过这个品几个月的毛利，正确结论是不投**，而不是把预算摊薄慢慢跑。

## 8. 止损：预先写死

每个投放 ASIN 在方案里就给出三条硬线，不到期再商量：

- 累计花费 ≥ 2 × 目标 CPA 且零单 → 降竞价一档（幅度按 `calculations.md` 的安全幅度表，本文件不另定上限）。
- 累计点击 ≥ 零订单门槛 且零单 → 停该关键词。
- 活动内关键词全部停 → 活动暂停，该 ASIN 转"非广告问题"或清货处理。

止损线只是预先约定的判断规则，不是写入授权。暂停/启用属于高影响状态动作，默认只列建议；用户明确允许状态调整后才 prepare，并按 SKILL.md 的写入边界单独审批。

## 9. 复盘记录

正式写入并回读成功后，用低销量节奏建记录：

```powershell
node "<本 skill 目录>/scripts/review-state.mjs" create --account <店铺> --marketplace <站点> --asins <ASIN1,ASIN2> --applied-at <ISO时间> --cadence low-volume --summary <简短说明>
```

`--cadence low-volume` 生成 7/30/90 三个节点；不传 `--cadence` 仍是默认的 3/7/14。`--summary` 里写明本轮的零订单门槛点击数、止损线和本轮轮投批次，这样到期时不必重新推导。`due` 返回的 `cadence` 字段用于区分两种节奏——看到 `low-volume` 就按本文件第 7 节判断，不要套用 `review-cycle.md` 的 3/7/14 结论标准；其余记录、到期查询和安全边界规则仍以 `review-cycle.md` 为准。

## 10. 输出格式

先给批次总览，再逐 ASIN 展开：

```text
批次：N 个 ASIN｜店铺/站点｜数据窗口
分档：A x 个 / B x 个 / C x 个 / D x 个
本轮投放：x 个        本轮不投：x 个（按原因分类）
本轮月度固定花费上限：
拿到结论的预计总成本：
判断周期：7/30/90 天 + 累计点击门槛
经济性状态：已验证 / 未完整验证
```

随后给出：分档表（ASIN、近 90 天单量、库存/库龄、Listing 与 Buy Box 状态、档位、判据来源）、本轮轮投计划与下一轮顺序、每个投放 ASIN 的关键词证据表和活动清单（关键词、匹配方式、竞价、日预算、创建后状态）、每个 ASIN 的三条止损线、D 档的非广告待办、缺失数据与置信度。

最后一次性询问用户是否确认当前版本的分档、轮投名单、词库、预算和竞价。确认前不 prepare；确认后任一字段变化都要重新展示并重新确认。
