# 广告持续复盘闭环

## 记录时机

方案、预览和正式执行必须区分：

- `applied`：正式写入成功，并已回读确认目标值。
- `reviewing`：到期后已开始重新取数。
- `completed`：第14天复盘结束，或运营明确终止。
- `blocked`：店铺、Listing、库存、Buy Box、数据或权限阻断。

分析方案和写入预览不保存为复盘任务。只有 `applied` 才产生复盘节点：默认节奏是第3、7、14天；月销约0–5单的长尾品用 `--cadence low-volume` 生成第7、30、90天节点，判断标准见 [low-volume.md](low-volume.md)，本文件下面的3/7/14节点说明不适用于该节奏。部分成功时只记录回读确认成功的对象；结果不明的对象不得记为成功。

## 创建记录

正式执行并回读后，为同一店铺、站点和一批ASIN创建一条记录：

```powershell
node "<本 skill 目录>/scripts/review-state.mjs" create --account <店铺> --marketplace <站点> --asins <ASIN1,ASIN2> --applied-at <ISO时间> --summary <简短说明>
```

若这些ASIN来自全店扫描，同时将对应扫描项标为 `applied`；开始到期复盘时标为 `reviewing`，第14天确认恢复时可标为 `improved`。扫描状态与复盘记录职责不同：前者防止重复派单，后者保存3/7/14天节点，二者都不构成写入授权。

输出的 `id` 是后续复盘编号。记录中可包含已核实的Campaign、广告组、关键词、预算、竞价或状态摘要，但禁止保存访问密钥、refresh token、cookie、完整环境变量或预览令牌。

默认状态目录是当前用户本机应用数据目录下的 `amz-cli/ads-reviews`。测试或受控部署可以显式传 `--state-dir <目录>`；不要把状态目录放进Skill安装包或Git仓库。

## 到期查询

```powershell
node "<本 skill 目录>/scripts/review-state.mjs" due
node "<本 skill 目录>/scripts/review-state.mjs" show --id <复盘编号>
```

`due` 只列任务，不读取Amazon、不生成写入预览、不修改广告。Agent拿到到期任务后必须按记录中的 `account` 和 `marketplace` 查询，禁止跨店铺寻找ASIN。

## 第3/7/14天判断

每轮使用一致且明确的归因窗口，记录数据截止时间和数据是否完整。若广告归因仍在回补，降低置信度，不把短期波动当成结论。

- 第3天：检查是否失控、不可售、丢Buy Box、库存风险、明显跑偏搜索词和异常花费。除明确止损条件外不频繁改价。
- 第7天：比较调整前后花费、点击、CPC、订单、CVR、销售额、ACOS及搜索词质量；样本充足后才决定保留、否定、降价、扩量或结构拆分。
- 第14天：判断方案是否达到用户目标，完成本轮、进入下一轮小步调整，或交给人工处理Listing、利润和库存问题。

没有利润率或目标ACOS时仍可比较流量、结构和相对表现，但所有盈利判断标记“经济性未验证”。不得把ACOS下降但销量断崖式下跌简单判为成功。

## 完成一个节点

查询、判断和人工确认完成后记录该节点：

```powershell
node "<本 skill 目录>/scripts/review-state.mjs" complete --id <复盘编号> --day 3 --result <结果摘要>
```

只能依次完成3、7、14天。第14天完成后状态变为 `completed`。若本轮又执行了新的预算、竞价、否定词或状态调整，应以新的回读值创建新记录，重新计算观察周期，不覆盖旧记录。

## 安全边界

- 本地记录不是Amazon事实；每次复盘必须重新通过 `amz-cli` 查询。
- 记录不得作为正式写入授权。每轮新调整都重新prepare、展示差异、由Cherry真人审批、正式执行并回读。
- 定时任务不得保存或复用15分钟预览令牌。
- 状态文件损坏、记录缺店铺/站点、ASIN非法或日期异常时停止该记录并报告，不猜测修复关键业务字段。
