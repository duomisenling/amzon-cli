# 选词：砍到 75 字符时留哪个词

标题从 190 砍到 75，等于删掉 115 字符的已收录内容。**最难的决定不是怎么写，是留哪个词。**选错主词就是丢自然流量，而且新标题一旦生效，旧词的收录也跟着没了。

这一步是**可选**的：没有任何外部数据时，用现有 listing + catalog 类目词照常改，但要在汇报里标注「选词未经流量验证」。别因为查不到数据就卡住不改——**超长标题拖着不改，亚马逊 AI 会替你改**。

## 🚧 唯一的硬边界：只影响选词，不影响事实

**外部数据（竞品标题、市场词、类目词）对「我的产品是什么」是零证据。**

竞品标题写 `wheat straw / BPA-free / dishwasher safe`，不代表我的产品是这些。这是整套流程里**最像样的编造侧门**——因为它看起来特别合理：同类目、同价位、词还很专业。

规则：

- 外部数据只回答**「这个词值不值得占标题的位置」**，只影响**用词和词序**。
- 它**不是** [writing-rules.md](writing-rules.md) 里的第六种来源标签，**不进 `<素材>` 区**，**不算任何出处**。
- 一个词只有在**我自己的素材里也有事实支撑**时才能用。市场热词是 `stainless steel garlic press`，但我的素材里查不到 stainless steel —— **这个词不能用**，哪怕它搜索量最高。
- 违反这条的典型症状：新标题里出现了原 listing 从没提过的材质或认证。**自检时专门看这一项。**

## 证据源（按硬度排序，能用上一档就别用下一档）

### 1. 自家广告搜索词报表 —— 最硬，真实成交

买家**真的搜了这个词、真的下了单**，比任何第三方估算都硬。

```bash
amz-cli ads profiles --account <店铺> --region <na|eu|fe>
amz-cli ads report --account <店铺> --profile-id <ID> --type search-terms \
  --start <YYYY-MM-DD> --end <YYYY-MM-DD>
```

返回 `searchTerm, impressions, clicks, cost, purchases7d, sales7d`。**单张报表最多 31 天，数据只保留约 95 天**，跨度更长要分段。profileId 分区域，站点和 `--region` 必须对上（DE 用 `--region eu`）。

判读：
- **有 `purchases7d` 的词优先留在标题**——这是买家用这个词买过你这个东西的直接证据。
- 有点击零转化的词不要放标题（那是 `ads wasted-spend` 的否定词候选，不是标题词）。
- 报表按 campaign 维度返回，要**过滤到本 SKU 相关的 campaign**，别把全店的词混着用。
- 没投过广告的 SKU 这条走不通，往下一档。

### 1.5 买家评论里的原话 —— 免费、且是买家自己的语言

买家管它叫什么，就该用什么词。评论里出现 `rusted metal box` 而文案写 `corten steel` —— 买家搜的是前者。

有 Sorftime 等评论 MCP 时可以拉自有评论和竞品评论。**只取「买家用什么词称呼这个产品和它的属性」**，不取事实断言（评论是线索不是出处，见 [writing-rules.md](writing-rules.md)）。

顺带留意**隐藏卖点**：买家反复自发夸、但 listing 根本没写的点。砍到 75 字符时「留哪个卖点」，这是最好的依据——**但写进标题前必须先问用户认不认**。

⚠️ **评论原话不得直接搬进标题，必须转写。** 取的是"用哪个词"，不是照抄句子。

### 2. 品牌分析 Search Query Performance —— 硬，但 CLI 暂未实现

需品牌备案。目前 amz-cli 没有这个命令（在 `local-delivery/待办.md` 的第一梯队）。**不要假装查过**——没有就说没有。

### 3. Sorftime / SIF 等市场 MCP —— 第三方估算，定相对优先级

Cherry 运行时有这些只读 MCP 时可用。用途：类目热词、需求趋势、竞品发现、竞争度。

约定沿用 [amazon-ads-strategist](../../amazon-ads-strategist/references/mcp-routing.md)：

- 工具名和参数**以当前会话实际 schema 为准**。文档里的示例名不存在时**不得猜造调用**。
- **不要用市场 MCP 反查本店 ASIN**（除非用户明确要求本品收录诊断）。
- **不向外部 MCP 发送**店铺密钥、refresh token、cookie、成本表或与任务无关的经营数据。
- 第三方搜索量是**估算**，按原口径标记，不要说成「Amazon 月度查询量」。只能用来排相对优先级，不能当绝对量。
- 一个 MCP 失败就用其他来源并降低置信度；全部失败就走第 4 档，**不虚构市场需求或竞品流量**。

### 4. 都没有 —— 用现有素材

- 现有标题和五点里**反复出现**的词（说明运营当初认为它重要）
- `catalog get` 返回的**类目名**（如 `Serving Trays`）——那是亚马逊自己的品类词
- 汇报时标注「**选词未经流量验证**」

## 选出来的词还要过意图匹配

高流量不能覆盖意图不匹配。把一个词放进标题前，先一句话说出它的**核心购买意图**，再对照我的产品形态、数量、规格、受众、场景：

- 意图一致且能直接承接 → 可以进标题
- 相邻但仍可能承接 → 放亮点或五点
- 意图偏离 → 不用（可能还是否定词候选）

例：市场热词 `garlic press set`（买家要一套），我的是单个 → **不能进标题**，进标题会拿到转化不了的流量。

## 词的归位

选出来的词按 [writing-rules.md](writing-rules.md) 的权重分配：

⚠️ **主词必须落在标题前 40 字符内。** 前 30–40 字符不只是权重最高的区段，**它还是手机上实际显示的部分**——主词被挤到后面，等于绝大多数买家根本看不见它。把主词填进草稿的 `mainKeyword`，校验器会替你查位置（超线报 `W_MAIN_KEYWORD_LATE`）。

| 位置 | 放什么 |
|---|---|
| 标题（紧跟品牌，**前 40 字符内**） | **唯一的主词**——证据最硬、意图最匹配的那一个 |
| 标题后半 | 差异化点 + 尺寸/变体 |
| 亮点 | 次级词 —— **标题装不下但值得收录的**，这是新规下最重要的一次搬运 |
| 五点第 1 条 | 剩下最重的词 + 最大差异化 |
| 后台搜索词 | 前面都没用过的长尾、同义词、常见错拼 |

## 批量时

**按「品类 + 站点」分组查一次，不要逐 SKU 查。**同品类同站点的市场词是共用的，20 个 SKU 查 20 次纯属浪费，还会把调用配额烧光。

广告搜索词报表也一样：**一次拉整个 profile 的报表**，再按 campaign / ASIN 拆到各 SKU，不要逐 SKU 发报表任务（报表要排队，实测经常 PENDING 好几分钟）。

## 汇报里要说清楚

每条改写的选词依据要能追溯，至少说明主词是怎么定的：

```
主词 serving tray —— 依据:自家广告搜索词报表 2026-07-01~07-31,
                     clicks 214 / purchases7d 18,本店真实成交
次级词 wheat straw —— 素材出处:catalog 材质字段 + MSKU;搬进亮点
未采用 bamboo tray —— Sorftime 显示需求更高,但素材无 bamboo 依据,不能写
```

最后一行是重点：**因为素材没依据而放弃的高流量词，要单独列出来**。这是在告诉用户「这个流量你现在吃不到，除非补素材证明产品确实是这个」——他可能真的能补。
