# 改写规则

标题、亮点（和顺带的五点）怎么写。硬上限见 [rules-2026.md](rules-2026.md)。

## 字符目标区间

**上限是亚马逊定的，下限只是目标。** 素材不够就写短——**绝不能为了凑字数注水或编造**。写短了在 `omitted` 里记一笔即可。这条优先级高于所有字数目标。

按语言给不同区间，因为德语/荷兰语/瑞典语的复合词一个就 20 多字符（`Aufbewahrungstasche`、`Kopfhörer-Hartschalenetui`），套英语的区间根本写不下「品牌 + 主词 + 差异化」。

| 语言 | 标题目标 | 亮点目标 |
|---|---|---|
| 英语 | 45–65 | 100–120 |
| 德语 / 荷兰语 / 瑞典语 / 波兰语 | 55–72 | 95–122 |
| 法语 / 意大利语 / 西班牙语 / 葡萄牙语 | 50–70 | 100–122 |

站点 → 语言：DE 德语；UK/GB/US/CA/IE 英语；FR 法语；IT 意大利语；ES 西班牙语；NL/BE 荷兰语；PL 波兰语；SE 瑞典语；BR 葡萄牙语；MX 西班牙语。

### 同语言不同站点也不一样

**英语不等于英语。** 差别不在语感，在买家能不能直接用：

- **CA**：单位用**公制**（cm / kg / L）——加拿大是公制国家，`12 inch` 买家得自己换算。素材只有英制时换算后写公制（这是单位换算不是编造，保留一位小数）。拼写跟英式的 `colour / centre / fibre`，但 `-ize` 结尾跟美式（`organize`）。**认证措辞不要照搬美国**：FDA、FCC 是美国机构，加拿大对应 Health Canada、ISED——把美国认证写进加拿大站文案就是不实陈述。
- **UK**：公制（cm / kg / L）；英式拼写 `colour / centre / metre / organise`。
- **US**：英制（inch / lbs / fl oz）为主，必要时括号补公制；美式拼写 `color / center / meter / organize`。

## 铁律一：只用素材里的事实

材质、颜色、尺寸、净重、板厚、认证、是否含赠品配件、防水防锈、是否可用洗碗机微波炉、产地、工艺——**素材里没有的，一律不许写**。想写但查不到依据的，写进 `omitted`（例：「素材未提供板厚，未写」）。

**宁可交一份信息少的稿，绝不交一份编造的稿。**

### 物理属性的判定：逐字出现，否则不写

材质、颜色、尺寸、重量、容量、件数这类**买家一眼能核对**的属性，只有在素材里**原文出现过**才能写。「看起来像」「这类产品通常是」「从图片推测」**都不算依据**。

- ✅ 素材标题有 `Wheat Straw Tray` → 可以写 wheat straw
- ✅ MSKU 是 `DEMO-Trays-Beige`、内部品名是「小麦秸秆托盘米色」→ 颜色有出处，可以写
- ❌ 素材里（含 MSKU、内部品名）**任何地方都没出现过颜色词** → 绝对不许写颜色，哪怕你觉得小麦秸秆制品通常就是米色

写之前对每个物理属性自问：**这个词在素材里出现过吗？** 没有就不写 + 记 `omitted`。

### 素材来源标签（只有这六种）

| 标签 | 是什么 | 算几个出处 |
|---|---|---|
| `<amazon_catalog>` | 亚马逊平台目录数据。权威度最高 | **1 个** |
| `<listing_local>` | 本站 listing 正文（标题/五点/亮点/**商品描述**/后台属性）。卖家自填，可能陈旧或从别的变体复制来 | **1 个** |
| `<listing_other_site>` | 同一商品在别站的 listing。**同一个实物，事实等同**，可直接本地化改写 | **1 个**（与本站是两次独立录入） |
| `<internal_record>` | 自家 ERP（内部品名 + MSKU + 内部分类）。品名和 MSKU 通常同一人同时录入，高度相关 | **两者合计 1 个** |
| `<variant_sibling>` | 同款不同颜色/尺寸的变体 | **不算出处**（那是另一个商品） |
| `<customer_reviews>` | 买家评论（自有或竞品） | **不算出处**（详见下条） |

- **没包在这六种标签里的任何文字都不是事实依据**——包括你的常识、对该品类的经验、从图片推测的东西。
- 同一标签块内部重复不算多个出处：五点里连写三次 pink 仍然只是 1 个出处。**商品描述和五点同属 `<listing_local>`**——描述里也写了 BPA-frei，加上五点里那次，仍然只算 1 个出处，仍然不能写。
- **跨语言的事实等价性不受语言影响**：他站是德语，`Weizenstroh` 与 `wheat straw` 是同一事实，**视同原文出现**。「逐字出现」针对的是「有没有这个事实」，不是「有没有这个拼写」。
- **变体兄弟只能借通用事实**（材质、结构、用途、清洁方式）。**颜色、尺寸、重量、件数必须用本站自己的**——从变体搬是买家一眼能看出的错。

### 评论是线索，不是出处

买家评论对标题极有价值——但**它是买家的说法，不是卖家能声明的事实**。三条纪律：

1. **评论不算出处，不能单独支撑任何物理属性。** 评论里说"很重、风吹不倒"不等于你可以写重量或防风。要写，先问用户确认，用户答复才是出处。
2. **竞品评论里夸的特性 ≠ 你的产品具备。** 那是**品类机会**，不是你的事实。写进文案前必须先问「我们的产品有没有这个」。素材里要区分标注 `[自有]` / `[竞品]`。
3. ⚠️ **评论原话不得直接搬进 listing，必须转写。** 照抄买家措辞既是版权风险，也会把买家的口语错误固化进你的文案。

那评论用来做什么？**两件事，都不涉及断言事实**：

- **买家用词**（最有价值）：买家管它叫 `rusted metal box` 而不是 `corten`。这直接决定标题用哪个词——**买家的原话比任何第三方估算都准**，而且免费。见 [keyword-choice.md](keyword-choice.md)。
- **隐藏卖点**：买家反复自发夸、但 listing 里根本没写的点。砍到 75 字符时「留哪个卖点」，这是最好的依据。**但它属于线索类，写进标题前必须问用户认不认。**

评论还有几层对**五点**有用，本 skill 也可以用：

- **购买动机**（为什么买：送礼 / 换旧的 / 装修）→ 五点的 benefit
- **使用场景**（实际用在哪、放哪里）→ 五点的 use case、亮点的场景词
- **竞品对比**（拿它和什么比、为什么选它）→ 五点的价值锚定
- **微吐槽**（反复出现的小抱怨）→ **不写进五点**，但要检查现有文案有没有和它打架

情感金句、QA 预期管理、A+ 模块不在本 skill 范围内。

### 素材说法不一致时：先分清哪一类

**不要一律绕开。** 一刀切会丢掉核心卖点——托盘这种品，买家第一个想知道的就是多大。

**① 真矛盾（两说法互斥）→ 数独立出处**
- 一方 ≥2 个独立出处、另一方只有 1 个 → **采用多数方**。
  例：颜色在 catalog、MSKU `DEMO-Trays-Beige`、内部品名三处都是 Beige，只有五点写 pink（多半是从粉色那条复制忘改）→ **写 Beige**。
- 数量相当或都只有 1 个 → **两个都不写，绕开**。
  例：catalog 写 `形状 = Square`，标题尺寸 22.5×31 是长方形 → 一比一 → **不提形状**，改说尺寸。

**② 详略差异（不互斥，一方更细）→ 只保留多数支持的部分**
  例：catalog 材质写 `wheat straw`，五点写 `wheat straw and PP` → 不冲突（复合材料 catalog 常只填主材），但 PP 只有一个出处 → **只写 wheat straw**。多出来的细节没有第二处佐证就不要。

**③ 口径不同（同一件事，数字接近或维度不同）→ 不算矛盾**
  例：标题写 `22.5 × 31 cm`，catalog 单品尺寸写 `31 × 2 × 23.5 cm`——31 对上了，22.5 与 23.5 差 1cm（多半内径/外径），2cm 是厚度填进了宽度栏。**照常写**，用出处多的那个。⚠️ 别把这类当矛盾绕开，尺寸是买家最需要的信息之一。

**记录要求**：① 类无论采用哪方**都要记进 `conflicts``；② 类砍掉的细节记进 `omitted`；③ 类两者都不必记。

### 存疑先问人，问不到才绕开

**对面坐着运营本人。** 素材里查不到的事实，运营多半知道——他手里有实物、有供应商资料、有内部表格。所以顺序是：

1. **先问。** 缺关键信息（尤其是颜色、材质、尺寸这类会进标题的属性）→ 直接问用户，别自己绕开。
2. **问到了就当素材用**，并在 `notes` 里记明「用户补充：材质为 304 不锈钢」——用户答复是**独立且可信的出处**。
3. **问不到、用户说不确定、或用户让你先出稿** → 才绕开不写，记进 `omitted`。
4. 任何时候都**不要写成「可能」「据称」蒙混过关**。要么有依据地写，要么不写。

**问题要让运营能答**，不要用内部术语：

- ✅「这款托盘是米色的吗？五点里写的是 pink，但货号和目录数据都指向米色。」
- ❌「colour 属性存在跨来源冲突，listing_local 与 amazon_catalog 出处数 1:2。」

`omitted` 和 `conflicts` **必须原样报给用户**——`conflicts` 是发现源数据错误的唯一线索（米色托盘的五点写着 pink，买家看得到，文案绕开只是治标）。

**批量时不要逐条问。** 攒成一份「待确认清单」按问题归类，一次问完，见 [batch.md](batch.md)。

#### 什么时候该「停下不出稿」，而不是绕开

绕开的前提是**少写一个次级信息，标题仍然成立**。有一类缺失不满足这个前提：

| 缺的是什么 | 怎么办 |
|---|---|
| 次级信息：板厚、认证、某个场景 | **绕开不写**，记 `omitted`，照常出稿 ✅ |
| **主词所依赖的核心事实**：这到底是个什么品类、核心材质、决定品类归属的关键规格 | ⛔ **停下不出稿**。标题的主词就建立在它上面，猜错等于整条标题错 |

例：不知道板厚 → 不写板厚，标题照出。
不知道这是托盘还是砧板 → **停**，因为主词没法定，出了也是错的。

批量时属于后者的条目**单独列出来、不出稿**，其余照常出——不要因为 3 条缺核心事实就把 20 条全停掉。

## 铁律二：违禁词，分两类

### 无条件禁（写了就是违规，跟产品好坏无关）

- **绝对化承诺**：Guaranteed / 100% / Never Fails / Risk-Free / Permanent / Instant
- **无根据最高级**：Best / Best Seller / #1 / Top Rated / Award Winning / Proven / Amazing
- **健康医疗宣称**：Cure / Treat / Heal / Prevent / Anti-viral / Antibacterial / 抗菌 —— 资质门槛极高、风险不对称，**即使素材里有也不写**
- **促销与价格**：bestseller / free shipping / on sale / 限时 / 立即购买 / 具体价格
- 各语言对应表达同样禁止：德 `garantiert` `beste`、法 `garanti` `meilleur`、意 `garantito` `migliore`、西 `garantizado` `mejor`、荷 `gegarandeerd` `beste`、波 `gwarantowane` `najlepszy`、瑞 `garanterad` `bästa`、葡 `garantido` `melhor`。

**替代写法**：用**具体可验证的客观描述**代替空泛最高级——不写 `Best quality steel`，写素材里确有的规格 `2 mm Corten steel`。

### 有凭证才可用

环保安全类：Eco-friendly / Sustainable / Biodegradable / Non-toxic / Chemical-free / BPA-free / Hypoallergenic / Organic。

- 素材里能找到**具体认证**（`LFGB certified`、`FDA 21 CFR`、`EN71-3`、报告编号）→ **可以写**，并把认证名一并写进文案（有证书就是真卖点，砍掉可惜）。
- 只有形容词、没有认证依据 → **不写**，记进 `omitted`（例：「原五点写 BPA-free，素材无认证依据，未写」）。

### 第三方品牌名

**标题和商品亮点里绝对不许出现第三方品牌**（Sony / JBL / Beats / Bose / Apple…），**即使原文案里有**。品牌注册方可据此投诉，轻则被迫改标题、重则下架。这两个字段都显示在**搜索结果页**，曝光面最大。

兼容信息写进**五点和后台搜索词**——那里只在详情页/后台，风险小得多，而且「适配 Sony WH-CH720N」本来就是买家要看的信息，放这里既安全又有用。

## 关键词归位

字段权重：**标题 > 亮点 + 第一条五点 > 其余五点 > 后台搜索词**。

- **标题**：品牌 → 主关键词（紧跟品牌）→ 差异化点 → 尺寸/变体。**只放一个主词。**
- **亮点**：次级关键词 + 材质 + 使用场景，最重要的放最前，**补标题没说的**。
- **五点**：共 5 条，第一条权重最高。**每条必须覆盖不同维度**（兼容性 / 结构设计 / 材质 / 使用场景 / 便携性 / 清洁保养），两条讲同一件事就是白占一个位置。
  反例：第 1 条列 JBL 兼容型号、第 2 条列 Sony 兼容型号——那是同一件事，应合并成「兼容 JBL 与 Sony 多个型号」，空出的位置写别的维度。
- **后台搜索词**：只放前面四处**都没用过**的词——长尾、同义词、常见错拼。无位置权重，空格分隔，不要逗号，不要重复。

### 标题 ↔ 亮点严禁重复

不只是同一个词，**同一个卖点换个说法复述也算重复**。两者并列展示给同一个买家，重复等于浪费黄金位。写完逐句比对。

⚠️ 别把两条规则混用：「同一个词最多两次」的作用域**只是标题本身**，不含亮点和五点；跨字段重复由这一条单独管。

### 标题被砍短时，关键词要有去处

标题从 190 字符压到 75，等于删掉 115 字符的已收录内容。**如果本次同时要改亮点，优先用亮点承接被砍掉但仍有价值的次级词**（材质、场景、规格）——这是新规下最重要的一次搬运。

## 五点的写法：两种语气混用

背景：Rufus（亚马逊 AI 导购）靠自然语言理解判断「这商品解决了买家说的问题吗」，**关键词堆砌对它起反作用**。但买家看五点是**扫**不是读，五条全写成长叙述句就是一堵墙。**不要五条一个腔调。**

**A. 规格事实型**（兼容型号、尺寸、件数、材质、认证）→ **直接陈述，规格前置**。这类信息买家是来「核对」的，包进叙述句只会让他找得更慢。
- ✅ `Fits JBL Tune 510BT, 520BT, 720BT and Sony WH-CH520, WH-CH710, WH-CH720N over-ear models.`
- ❌ `Whether you own a JBL or a Sony, you'll find that this case has been thoughtfully designed to accommodate...`（把型号埋进了废话里）

**B. 体验/场景型**（好不好用、解决什么麻烦、什么时候用）→ **写成对买家问题的回答**。
- ✅ `Presses unpeeled cloves straight from the bulb, so you skip peeling and rinse the chamber under the tap when you're done.`
- ❌ `Stainless Steel Garlic Press, Easy Clean, Durable`（罗列形容词，Rufus 解析不出信心）

⚠️ **B 型最容易变成编造的侧门。** 铁律一枚举的都是**物理属性**，而 B 型写的是用途、省了什么麻烦、什么场合用——**这些不在那张清单上，所以清单拦不住**。规则：**场景和收益必须是素材中已有结构或功能事实的直接后果。**

- ✅ `so you skip peeling` ← 素材写了「能压带皮蒜瓣」，跳过剥皮是直接后果
- ✅ `stack together for storage` ← 素材写了 stackable
- ❌ `perfect for busy weeknight dinners`（凭空假设使用场合和频次）
- ❌ `keeps your countertop tidy`（效果承诺，素材没依据）
- ❌ `ideal for families with young children`（假设人群）
- ❌ `you'll love how effortless it feels`（情绪渲染）

写每条 B 型时自问：**这句话是从素材里哪个事实推出来的？** 指不出就不写这条，或换个能指得出的角度。

**配比**：5 条里通常 **1–2 条 A 型 + 3–4 条 B 型**。规格密集的品（电子配件、兼容类）可到 2–3 条 A 型；生活家居类 B 型多一些。**第 1 条按这个品最强的差异化点选语气，不要机械套配比。**

⚠️ **素材不足只写得出 3 条时，按实际条数等比例缩，并优先保 A 型。** 规格事实是现成的，B 型要靠推导——缺料时硬凑 B 型正是最容易注水的做法。宁可 3 条里 2A1B，也不要为了配比编出两条场景。

**句首位置**：第 1 条五点是仅次于标题的权重位，**句首必须是本条最重的关键词**（A 型放规格词，B 型放功能/品类词）。不要用 `Whether you...` `Designed to...` 这类虚词开头把最贵的位置浪费掉。

## 整套重写，不是打补丁

**进了本次优化的 listing，标题 + 亮点 + 五点一次全写。** 校验带 `--complete`，缺任一字段报 `E_INCOMPLETE_SET`。

| 缺口编号 | 字段 | 上限 |
|---|---|---|
| CK05 | `title` | 75 字符（媒体类目 200） |
| CK10 | `highlights` | 125 字符 |
| CK04 | `bullets` | 5 条（至少 3 条才算一套） |
| CK06 | `search_terms` | 249 字节（默认不做） |

**以编号为准**，中文措辞会变（同一个缺口出现过「亮点未填」和「亮点缺」两种写法）。

为什么不能只改缺的那一个：

- 标题砍到 75 字符，删掉的 100 多字符里那些有价值的词**必须有地方去**——只能是亮点。标题改了亮点不改，等于把词直接扔了。
- 亮点内容一变，五点就得重新分配维度，否则和亮点撞车（亮点只有 125 字符且在搜索结果页，被复述一遍就是白扔黄金位）。
- 三个字段的关键词归位是一次性算出来的，拆开做必然重复或漏词。

⚠️ **代价要说清楚：这会覆盖运营已经写好的五点和亮点。** 所以汇报必须逐字段摆「当前值 → 新值」，并明确告诉用户可以点名保留某个字段。**用户说保留的，从 patch 里删掉那一项，其余照写**——不要整条跳过。

**后台搜索词仍然默认缓做**：模型在猜买家会怎么搜，没有真实搜索数据支撑，实测反馈「词不准确」。等接上品牌分析 Search Query Performance / 广告搜索词报告再做。用户明确要求时才写，并说明这层限制。

## 输出格式

```json
{
  "title": "新标题 或 null",
  "highlights": "新商品亮点 或 null",
  "bullets": ["五点1", "..."],
  "searchTerms": "后台搜索词 或 null",
  "omitted": ["素材未提供板厚，未写"],
  "conflicts": [
    {
      "field": "颜色",
      "claims": "listing_local 的五点写 pink；amazon_catalog 与 internal_record 写 Beige",
      "chosen": "Beige",
      "reason": "2 个独立出处对 1 个，且 catalog 为平台侧数据"
    }
  ],
  "notes": "一句话说明这次改动的思路（中文，给用户看）"
}
```

`null` = 本次不改这个字段。**JSON 的 key 一律用英文**，值用中文/目标语言；`omitted` 和 `notes` 用中文，文案字段用站点语言。

**不改的字段仍然要读它的现值**——「标题↔亮点不重复」要拿标题现值去比；改标题时被砍掉的关键词要判断能不能塞进本次要改的其他字段。
